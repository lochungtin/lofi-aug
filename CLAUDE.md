# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

LOFI (**Lo**w-**Fi**eld) corrupts good MRI scans to look like low-field open-magnet scans. It is pre-release. **This file is the authority on conventions and design as built.** The research (the calibration study, the research notes behind the physics and the crosstalk model, and the downstream segmentation studies) is kept outside this package, in the `_lofi` folder of `lochungtin/PhD_Codebase`. No patient data belongs in this repository.

## Tooling

- PyPI name `lofi-aug`, import name `lofi`, `src/lofi` layout, built with hatchling, managed with uv.
- Commands:
  - `uv sync --extra dev --extra io`: install.
  - `uv run pytest`: tests. The adapters' tests skip without their extras: `uv run --extra dev --extra io --extra monai --extra torchio pytest tests/test_integrations.py`, then `uv sync --extra dev --extra io` to restore the env.
  - `uv run ruff check . && uv run ruff format .`: lint and format (markdown is excluded from formatting).
  - `uv run mypy`: strict, checks `src/`.
- Extras: `[io]` (nibabel; needed by the command line), `[viz]`, `[monai]`, `[torchio]`, `[dev]`.
- `tests/helpers.py` has `phantom` and `quiet` (a profile with every stage neutral, so a test switches on the one it is about). The `ndim` fixture covers 2D and 3D.
- CI (`.github/workflows/branch-ci.yml`) runs on pushes to `main` and on pull requests. It installs CPU-only torch via `uv pip install --torch-backend=cpu`, runs lint + mypy on 3.12, tests on 3.10–3.13, and tests the MONAI and TorchIO adapters in their own job. `pytest --cov` fails under 85 % coverage. On `main` it then builds, publishes to TestPyPI and bumps the version from Conventional Commits; the pushed tag triggers `release.yml` (PyPI and a GitHub release). The version comes from the git tag (hatch-vcs). Commit with Conventional Commits, and don't edit the version by hand.

## Conventions that must hold everywhere

- **Only intensities change.** No stage may move anatomy, which is why registration jitter is modelled as slab offsets and not as a warp. Grid changes (`output_spacing_mm`, `canvas_mm`) go through `Result.padding` and `augment.resample_label`, so labels follow the image.
- **Stages run in acquisition order.** Noise goes on the acquired grid, before the magnitude. Adding it later loses the Rician floor and the grain.
- **Relative units.** `corrupt` normalises to the foreground median, so `sigma` and `contrast.values` are ratios to it. Scanner units only return through `output_scale`.
- **`noise.sigma` is per real channel, on the acquired grid.** `kspace.crop` rescales so a uniform object keeps its intensity, which makes unit noise in k-space unit noise per acquired voxel.
- **Source noise is subtracted, not added on top** (`carried` in `corrupt`), after attenuating it by the voxel-volume change.
- **`kspace.crop` keeps the FOV aligned.** DC sits at `n // 2`, which is a different physical place on each grid, so without its linear phase an even-sized crop shifts the image.
- **Profiles are strict.** Unknown keys raise. `[low, high]` is drawn per sample; a number is fixed.
- **`physics.scale_covariance` keeps coil and sample noise apart.** Coil noise is uncorrelated between channels, so correlation falls by `a²/η`. The research note's single scalar `η` is not what is implemented.

## The bundled profile

`low_field_breast` is fitted to 0.5 T open-magnet breast scans whose volumes are not single acquisitions: two GRE scans (30° and 60°) combined by registration and resampled to 2 mm isotropic. That recon chain is why the profile has `n_averages: 2`, 6 mm slices (the z steps repeat every 3 voxels) and `slice_jitter_mm`. `target_b0` records the field and does not affect a calibrated profile. Ghosting is set by hand: fitting it to air spread failed, because the target's "air" includes the lungs. The profile is regenerated by the calibration study outside this repository, so edit it there.
